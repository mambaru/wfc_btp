# JSON-RPC API

> **wrtstat:** методы записи `push`, `multi_push`, `del` и формат полей метрик (`ts`, `avg`, `count`, перцентили, `data`) определены библиотекой wrtstat — [GitLab](https://gitlab.mamba.ru/cpp/wrtstat/-/blob/master/docs-md/README.md?ref_type=heads) · [GitHub](https://github.com/mambaru/wrtstat/blob/master/docs-md/README.md). Ниже описаны параметры и поведение на стороне btpd; подробнее о клиентской агрегации и метрах — в документации wrtstat.
>
> **Тип значений:** все метрические поля (`avg`, `min`, `max`, перцентили, элементы `data`) — **целые числа** (`wrtstat::value_type`, целочисленный тип). Дробные значения в JSON не используются; типичный сценарий — латентность в микросекундах или другая целочисленная величина.

Модуль `ag-module` экспортирует методы через два компонента:

| Компонент | Роль | Тип методов |
|-----------|------|-------------|
| **service** | Локальная обработка | `invoke_method` — вызов напрямую в домен |
| **gateway** | Удалённый вызов / прокси | `call_method` — перенаправление на целевой интерфейс |

Gateway реализует интерфейс `ibtp` и делегирует вызовы удалённому сервису. Некоторые методы в gateway намеренно возвращают `null` (см. примечания ниже).

Все методы используют стандартный JSON-RPC 2.0 через WFC/wjrpc. Ниже для каждого метода приведены полные примеры **запроса** и **ответа** (поле `result`).

## Методы записи (wrtstat)

### `push`

Запись одной агрегированной метрики.

**Запрос:**

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `name` | string | да | Имя метрики (может содержать разделители для иерархии) |
| `ts` | integer | нет | Временная метка (в единицах `resolution` из конфига) |
| `avg` | integer | нет | Среднее значение (целочисленное) |
| `count` | integer | нет | Количество измерений |
| `lossy` | integer | нет | Количество потерянных измерений |
| `min` | integer | нет | Минимум |
| `max` | integer | нет | Максимум |
| `perc50` | integer | нет | 50-й перцентиль |
| `perc80` | integer | нет | 80-й перцентиль |
| `perc95` | integer | нет | 95-й перцентиль |
| `perc99` | integer | нет | 99-й перцентиль |
| `perc100` | integer | нет | 100-й перцентиль (максимум по выборке) |
| `data` | array of integer | нет | Сырые reduced-данные для агрегации на стороне сервера |

**Ответ:**

| Поле | Тип | Описание |
|------|-----|----------|
| `status` | bool | `true` при успехе |

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "push",
  "params": {
    "name": "service~~requests~~latency",
    "ts": 1717550400,
    "avg": 125,
    "count": 100,
    "min": 1,
    "max": 500,
    "perc50": 10,
    "perc80": 25,
    "perc95": 100,
    "perc99": 200,
    "perc100": 500
  },
  "id": 1
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "status": true
  },
  "id": 1
}
```

### `multi_push`

Пакетная запись нескольких метрик.

**Запрос:**

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `data` | array | — | Массив объектов `push` |
| `sep` | string | `"~~"` | Разделитель имён |
| `legend` | array of string | `[]` | Легенда для сжатия имён (см. ниже) |

**Ответ:**

| Поле | Тип | Описание |
|------|-----|----------|
| `status` | bool | Общий статус операции |
| `error` | string | Текст ошибки (при recompact) |

Перед обработкой вызывается `basic_packer::recompact` — нормализация и уплотнение пакета.

**Сжатие имён через `legend`:**

При непустом `legend` имена вида `name~~name1~~name2~~name3` преобразуются в `0~1~2~3`, где числа — индексы в массиве `legend`.

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "multi_push",
  "params": {
    "sep": "~~",
    "data": [
      {
        "name": "service~~requests~~latency",
        "ts": 1717550400,
        "avg": 125,
        "count": 100,
        "min": 1,
        "max": 500,
        "perc50": 10,
        "perc80": 25,
        "perc95": 100,
        "perc99": 200,
        "perc100": 500
      },
      {
        "name": "service~~requests~~count",
        "ts": 1717550400,
        "avg": 1,
        "count": 1000
      }
    ]
  },
  "id": 2
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "status": true
  },
  "id": 2
}
```

**Пример ответа при ошибке recompact:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "status": false,
    "error": "recompact failed: ..."
  },
  "id": 2
}
```

### `del`

Удаление метрик по именам.

**Запрос:**

| Поле | Тип | Описание |
|------|-----|----------|
| `names` | array of string | Список имён для удаления |

Удаляются метаданные из `key_storage` и все временные ряды из `data_storage`. Ошибки удаления отдельных имён логируются, но не прерывают обработку остальных.

**Ответ:** пустой объект (без полей).

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "del",
  "params": {
    "names": [
      "service~~requests~~latency",
      "service~~requests~~count"
    ]
  },
  "id": 3
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {},
  "id": 3
}
```

## Методы чтения

### `get`

Чтение временного ряда одной метрики.

**Запрос:**

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `name` | string | — | Имя метрики |
| `ts` | number | `0` | Начальная временная метка. `0` — `(now - TTL) * resolution` |
| `offset` | number | `0` | Пропустить первые N точек |
| `limit` | number | `0` | Максимум точек. `0` — до `result_limit` из конфига |
| `power` | bool | `false` | Вернуть «мощностные» значения (avg², perc×count и т.д.) |

**Ответ:**

| Поле | Тип | Описание |
|------|-----|----------|
| `counters` | array | Массив агрегированных точек (compact-формат) |

**Формат элемента `counters` (compact array):**

```
[ts, avg, count, perc50, perc80, perc95, perc99, perc100, min, max, lossy]
```

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "get",
  "params": {
    "name": "service~~requests~~latency",
    "ts": 1717546800,
    "offset": 0,
    "limit": 100,
    "power": false
  },
  "id": 4
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "counters": [
      [1717550400, 125, 100, 10, 25, 100, 200, 500, 1, 500, 0],
      [1717550460, 112, 95, 10, 22, 90, 180, 450, 1, 450, 2]
    ]
  },
  "id": 4
}
```

### `multi_get`

Чтение временных рядов нескольких метрик.

**Запрос:**

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `names` | array of string | — | Список имён |
| `ts` | number | `0` | Начальная временная метка |
| `offset` | number | `0` | Смещение |
| `limit` | number | `0` | Лимит точек на метрику |
| `power` | bool | `false` | Мощностные значения |

**Ответ:**

| Поле | Тип | Описание |
|------|-----|----------|
| `data` | array | Массив `{name, counters}` |

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "multi_get",
  "params": {
    "names": [
      "service~~requests~~latency",
      "service~~requests~~count"
    ],
    "ts": 1717546800,
    "offset": 0,
    "limit": 100,
    "power": false
  },
  "id": 5
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "data": [
      {
        "name": "service~~requests~~latency",
        "counters": [
          [1717550400, 125, 100, 10, 25, 100, 200, 500, 1, 500, 0]
        ]
      },
      {
        "name": "service~~requests~~count",
        "counters": [
          [1717550400, 1, 1000, 1, 1, 1, 1, 1, 1, 1, 0]
        ]
      }
    ]
  },
  "id": 5
}
```

> **Gateway:** метод `multi_get` в gateway возвращает `null`. Используйте service или прямой вызов домена.

### `merge`

Запись готового набора агрегированных точек (без промежуточной агрегации в кэше).

**Запрос:**

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | string | Имя метрики |
| `counters` | array | Массив точек в compact-формате |

**Ответ:**

| Поле | Тип | Описание |
|------|-----|----------|
| `status` | bool | Результат операции |

Используется для импорта данных или восстановления из резервной копии.

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "merge",
  "params": {
    "name": "service~~requests~~latency",
    "counters": [
      [1717550400, 125, 100, 10, 25, 100, 200, 500, 1, 500, 0],
      [1717550460, 112, 95, 10, 22, 90, 180, 450, 1, 450, 2]
    ]
  },
  "id": 6
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "status": true
  },
  "id": 6
}
```

## Методы поиска и навигации

### `select`

Поиск метрик по префиксу и суффиксу с сортировкой.

**Запрос:**

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `prefix` | string | `""` | Префикс имени |
| `suffix` | string | `""` | Суффикс имени |
| `offset` | number | `10` | Смещение в результатах |
| `limit` | number | `0` | Лимит (0 — без ограничения) |
| `sortby` | string | `""` | Поле сортировки — см. [допустимые значения `sortby`](#допустимые-значения-sortby) |
| `power` | bool | `true` | Использовать мощностные значения для сортировки |

**Ответ:**

| Поле | Тип | Описание |
|------|-----|----------|
| `names` | array | Массив `[name, value]` — compact-пары |

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "select",
  "params": {
    "prefix": "service~~requests",
    "suffix": "",
    "offset": 0,
    "limit": 10,
    "sortby": "perc80",
    "power": true
  },
  "id": 7
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "names": [
      ["service~~requests~~latency", 2500],
      ["service~~requests~~count", 1000]
    ]
  },
  "id": 7
}
```

---

### `get_names`

Аналог `select`, но возвращает имена с временной меткой последнего обновления.

**Запрос:** те же поля, что у `select`, но `power` по умолчанию `false`. Поле `sortby` — см. [допустимые значения `sortby`](#допустимые-значения-sortby).

**Ответ:**

| Поле | Тип | Описание |
|------|-----|----------|
| `names_ts` | array | Массив `{name, value}`, где `value` — `last_update` |

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "get_names",
  "params": {
    "prefix": "service~~requests",
    "suffix": "",
    "offset": 0,
    "limit": 10,
    "sortby": "count",
    "power": false
  },
  "id": 8
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "names_ts": [
      {"name": "service~~requests~~latency", "value": 1717550460},
      {"name": "service~~requests~~count", "value": 1717550400}
    ]
  },
  "id": 8
}
```

### `tree`

Построение дерева имён метрик.

**Запрос:**

| Поле | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| `prefix` | string | `""` | Префикс для фильтрации |
| `sep` | string | `"~~"` | Разделитель уровней дерева |
| `depth` | number | `1` | Глубина обхода |
| `offset` | number | `0` | Смещение |
| `limit` | number | `100` | Лимит результатов |
| `ntype` | string | `""` | Тип узла — см. [допустимые значения `ntype`](#допустимые-значения-ntype) |
| `sortby` | string | `""` | Поле сортировки — см. [допустимые значения `sortby`](#допустимые-значения-sortby) |
| `by_power` | bool | `false` | Мощностные значения для сортировки |

**Ответ:**

| Поле | Тип | Описание |
|------|-----|----------|
| `names` | array | Массив `[name, value]` |

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "tree",
  "params": {
    "prefix": "service",
    "sep": "~~",
    "depth": 2,
    "offset": 0,
    "limit": 100,
    "ntype": "all",
    "sortby": "perc80",
    "by_power": false
  },
  "id": 9
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {
    "names": [
      ["service~~requests", 25],
      ["service~~errors", 10]
    ]
  },
  "id": 9
}
```

При `prefix: "service"`, `sep: "~~"`, `depth: 2` вернутся узлы второго уровня внутри `service`.

## Допустимые значения `sortby`

Поле `sortby` используется в методах `select`, `get_names` и `tree`. Передаётся строкой; десериализуется через `sort_by_json`.

| Значение | Enum | Описание |
|----------|------|----------|
| `""` | `NOSORT` | Без сортировки (эквивалент `nosort`) |
| `"nosort"` | `NOSORT` | Без сортировки |
| `"avg"` | `AVG` | По среднему (`avg`) |
| `"count"` | `COUNT` | По количеству измерений |
| `"perc50"` | `PERC50` | По 50-му перцентилю |
| `"perc80"` | `PERC80` | По 80-му перцентилю |
| `"perc95"` | `PERC95` | По 95-му перцентилю |
| `"perc99"` | `PERC99` | По 99-му перцентилю |
| `"perc100"` | `PERC100` | По 100-му перцентилю (максимум выборки) |
| `"min"` | `MIN` | По минимуму |
| `"max"` | `MAX` | По максимуму |
| `"lossy"` | `LOSSY` | По количеству потерянных измерений |

Любое другое значение при strict-десериализации JSON считается ошибкой.

При `power: true` (в `select` / `get_names`) или `by_power: true` (в `tree`) для сортировки используются «мощностные» значения метрик (см. [флаг `power`](#флаг-power)).

---

## Допустимые значения `ntype`

Поле `ntype` используется только в методе `tree`. Передаётся строкой; десериализуется через `tree_node_json`.

| Значение | Enum | Описание |
|----------|------|----------|
| `""` | `ANY` | Любые узлы (эквивалент `all`) |
| `"all"` | `ANY` | Любые узлы |
| `"leaf"` | `LEAF` | Только листья (конечные метрики) |
| `"branch"` | `BRANCH` | Только промежуточные узлы |

## Методы обслуживания

### `compact`

Запуск компакции RocksDB (key_storage и все шарды data_storage).

**Запрос:** без параметров.

**Ответ:** пустой объект.

**Пример запроса:**

```json
{
  "jsonrpc": "2.0",
  "method": "compact",
  "params": {},
  "id": 10
}
```

**Пример ответа:**

```json
{
  "jsonrpc": "2.0",
  "result": {},
  "id": 10
}
```

**Поведение:**

- Если callback не передан (fire-and-forget) — компакция выполняется асинхронно через workflow.
- Если callback передан — компакция выполняется синхронно в текущем потоке.

## Флаг `power`

При `power: true` значения в ответе преобразуются для «мощностной» агрегации (результат остаётся целочисленным):

- `avg` → `avg × avg`
- `min`, perc*, `max` → умножаются на `count`

Используется при последующем объединении метрик с разным `count`.

## Именование метрик

Имена метрик — произвольные строки. Иерархия задаётся разделителем (по умолчанию `"~~"`):

```
service~~component~~metric~~submetric
```

Разделитель настраивается в запросах `tree` / `multi_push` через поле `sep`.
